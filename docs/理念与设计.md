# slab：一颗能长出 coding agent 的 shell 种子

slab 是一个实验，不是又一个「更好用的 AI 编程助手」。

它问的是一件很窄、也很硬的事：**只用 POSIX `/bin/sh`，能不能撑住一个带工具的 coding agent 主循环？** 如果能，这颗种子换一台机器、换一个项目，还应该能再长出来。如果不能，缺口要写清楚，而不是用 Python、用容器、用第二套实现把洞补上，然后对外说「这是 shell」。

仓库里真正要带走的是 `seed.sh`。`bin/agent` 是种子自己写的薄入口。你后来让 agent 在某个目录里改的文件、写的脚本、做的网页，属于那个项目，不属于种子。

契约细节见 [三舱安装包设计](superpowers/specs/2026-08-13-seed-package-design.md)。本文讲理念和为什么这样长。

---

## 1. 这是什么

把 `seed.sh` 放进一个有 `/bin/sh`、curl、jq 的环境，再给它一个模型的 API Key。它会：

1. 把凭据写进 `.env`（权限 600）
2. 在当前目录写下 `bin/agent`、`bin/edit`、`bin/shell`、`bin/llm`
3. **自己看磁盘**，不信模型口头说「装好了」。安装不叫模型。

装完之后，人在任意项目里：

```sh
cd 你的项目
sh /path/to/slab/bin/agent
```

打开就是 `>`。你说一句话，它用两个工具干活，最后只印一段回答。没有开场白，过程不刷屏。

工作区永远是你启动它时的当前目录。换项目就先 `cd`，不要在种子里写死某台电脑的路径。

它不是：

- Claude Code / Codex 的复刻
- 沙盒里的玩具 REPL
- 「每条任务让模型写一段 controller 再自己调 LLM」的极端自举
- 用 Python 实现 loop、再套一层 `sh` 启动器的噱头

---

## 2. 理念

### 2.1 测的是天花板，不是便利

现在的 coding agent 几乎都有一层厚运行时：Node、Python、Rust、一整柜工具（读文件、grep、glob、子代理、todo）。那套东西很强，但测不出 **shell 自己能走多远**。

slab 把外壳限制死：

- 主 loop 必须是 `/bin/sh`
- 种子自带的工具必须是 shell 调 curl / jq，不能再请一种语言来「代打」
- 协议必须是 API 的 `tool_calls`，不能再发明一套 `<ACTION>` 文本方言

限制只罩住 **种子和 `bin/agent` 的主 loop，以及那两个自带工具**。模型之后在工作区里写 Python、Go、网页、测试，随便。那是产物在干活，不是外壳在作弊。

如果 loop 里出现了 Python，这个实验就名不副实：测到的是「shell 当启动器」，不是 shell 的天花板。

### 2.2 外壳拥有循环，模型拥有判断

有一种更极端的设想：不要固定 loop，每条任务让模型写一整段控制器，自己再去调 LLM。那在纸上很「自举」，在机器上不稳定、难复用、种子也很难验收。

slab 不走那条路。循环是写死的：

```text
带 tools 问模型
  → 有 tool_calls：按顺序执行，把结果喂回去
  → 没有 tool_calls：这一轮结束
```

模型决定「看什么、改什么、何时停」。外壳决定「怎么问、怎么执行、怎么停、怎么对人说话」。人看到的是引导和最后回答，不是思考流。

### 2.3 工具要少到不能再少

模型对外只有两个工具：

| 工具 | 做什么 | 不做什么 |
|---|---|---|
| **shell** | 在一个不退出的本机登录壳里跑一条命令 | 不每条命令新开一个进程，所以 `cd` / `export` 还在 |
| **edit** | 在文件里把一段旧文本唯一替换成新文本 | 不模糊匹配；出现 0 次或 2 次以上就失败、不改文件 |

看文件、列目录、跑测试、新建文件，全部走 shell（`cat`、`ls`、`git`、`cat > file`）。没有 read / grep / glob / todo / 子代理。

少不是因为懒，是因为协议要稳。工具一多，种子和产物就会长成两套，模型也会把时间花在选工具上。两个工具够写代码；不够的部分，让模型用 shell 自己长。

### 2.4 不信模型的嘴，信磁盘

安装结束时模型很会说「好了」。slab 不当真。种子自己检查：

- `bin/agent` 等入口在不在、语法过不过
- `.env` 在不在、有没有 key（不把 key 印出来）
- 用假的一轮 `tool_calls`（不联网）驱动产物，必须在安装目录**之外**的临时目录里跑
- 无参数打开 `bin/agent` 只有 `>`，EOF 后干净退出
- shim 里没有写死的 `/Users/...`、`/home/...`

真模型黑盒任务不放在安装结尾。那是你之后在自己项目里用的。

### 2.5 一份种子，跟宿主走，不携带住址

Mac 自带 Bash 3.2，Debian 上 `/bin/sh` 常常是 dash，登录壳又可能是 zsh 或 bash。如果按「Bash 5 脚本」来写，就要分叉，实验就碎了。

所以：

- **外壳语法**是 POSIX `/bin/sh`，全世界一份
- **命令真正跑在哪个壳里**，运行时看 `$SHELL`，没有就 `/bin/sh`
- **edit** 不调用 GNU/BSD 两套 `sed -i`，用 jq 做唯一替换
- **超时、截断、杀子进程**用 `sleep` / `dd` / `ps`，不用 `timeout(1)`、perl、python、`pgrep`、`head -c`

换机器把仓库拷过去，自己准备 `.env`。不要把旧电脑的绝对路径写进种子。已经在 macOS 和 Debian（dash）上用同一份文件跑通过。

原生 Windows cmd / PowerShell 没有这套 POSIX 环境，不是「再写一套 Windows 版」，而是换 Git Bash / WSL，或以后再谈虚拟机。那是环境边界，不是第二种实现。

## 3. 两层：种子和产物

这是整件事里最容易混的地方。

| | 种子 `seed.sh` | 产物 `bin/agent` |
|---|---|---|
| 你是谁 | 无头安装包 | 给人用的编程窗口 |
| 对人 | 不说话；最多 `installed:` | `>` + 最后回答 |
| 对模型 | 要，用来确认安装 | 要，用来干活 |
| 工具 | 持久 shell + edit | **同一对，同一个 loop** |
| 工作区 | 安装目录 | **启动时的 `$PWD`** |

`bin/agent` 不是模型写出来的另一套程序。安装把种子里同一套 loop 整份写进去，默认入口是 agent。装完可以删掉 `seed.sh`。`--edit`、`--llm`、`--shell` 指向这份 `bin/agent`。改 loop 只改 `build/`，再打包、再安装。

安装时模型**不会**再为这台机器写一套 bash 工具。工具已经在 `seed.sh` 里。模型只被要求：看一眼 shim、确认引导语、不要重跑安装器、不要写死路径。特化只有一件事——持久 shell 跟这台机器的登录壳走。

## 4. 单文件，三舱

设计源在 `build/`：loop、提示词、任务、工具各是各的文件。`sh build/pack.sh` 打成仓库根上的 `seed.sh`。运行时仍是一个文件，不依赖 `build/`。

```text
build/
  loop.sh / model.sh / edit.sh / shell.sh / ...
  prompts/product-system.txt
        ↓ pack.sh
seed.sh   打包态，给人带走
```

改脾气改 `build/prompts/`。改骨架才动 `build/loop.sh`。不要手改 `seed.sh`。

对模型说英文。种子不对人说话：状态和错误是英文机器话。产物打开就是 `>`，最后回答给人看。种子的 SYSTEM 写明：你是安装器，不是聊天窗口。产物的 SYSTEM 写明：你是 coding agent，过程不要往终端倒。

## 5. 两个工具怎么工作

### 5.1 持久 shell

背后一个不退出的进程。种子写出一小段 `worker.sh`，用 `$SHELL` 拉起来，标准输入关掉，避免命令停着等人打字。

每次调用：往会话目录丢一条命令，等它写完 stdout / stderr / 退出码 / 当前目录，再把这四样格式化成观察结果喂回模型。同一段会话里 `cd` 和 `export` 还在。

- 种子安装 = 一段会话
- `bin/agent` 从打开到退出 = 一段会话
- 同一次窗口里的第二句话，还是这段会话

超时默认 180 秒，输出超过 16KiB 会截断并标明。超时后会杀掉这棵进程树，再拉起一个新 worker，避免一条挂死的命令把整个 agent 卡死。

这不是「我们实现了一个 bash」。这是「我们租用了这台机器上已经存在的那个壳」。

### 5.2 edit

三个参数：路径、旧文本、新文本。旧文本必须在文件里**恰好出现一次**。

用 jq 做字符串切分，不碰 `sed -i`。所以不用为 GNU sed 和 BSD sed 写两套。看、建、测，走 shell。

## 6. 循环长什么样

种子和产物共用这个形状：

1. messages 以 SYSTEM 开头，再加上当前任务或用户那句话
2. 请求带 `tools`：shell、edit；一次 JSON，不走 SSE
3. 有 `tool_calls`：按顺序执行，以 tool 角色喂回
4. 没有 `tool_calls`、只有文本：产物把这段当最后回答印给人
5. 产物每条任务默认 20 轮，可用环境变量改
6. 超限：产物印英文 `round limit reached; task unfinished`，窗口不崩

安装不跑这个循环。思考和正文不进终端。没有 token 心跳。

证据分别落在：

- 种子：`$INSTALL/.runs/<utc>-<pid>/`
- 产物：调用目录下 `.agent-runs/<utc>-<pid>/`

里面有 messages、模型响应、每次工具的参数和结果、usage。没有 key，没有 Authorization。

## 7. 凭据和工作区

第一次：

```sh
sh seed.sh deepseek sk-xxxx
```

Key 写进**调用 seed 时的当前目录** `.env`，并复制一份到安装目录。之后：

```sh
sh seed.sh          # 重装，不再把 key 贴在命令行
sh bin/agent        # 读 .env
```

读取顺序：环境变量 → 当前目录 `.env` → 安装目录 `.env`。

只写 `sh seed.sh deepseek`（没有 key）不会把 `deepseek` 当成安装目录。那是一个已经修掉的误装。

工作区规则就一句：**`bin/agent` 被调用时的当前目录。** 种子可以知道自己装在哪，但不得把某台机器的家目录写进产物。shim 用 `dirname` 找 `seed.sh`，不写 `/Users/你/...`。

## 8. 目录里都是什么

克隆下来之后，人需要的是这些：

```text
build/                  设计源（loop、提示词、工具，分开改）
seed.sh                 打包态 / 运行时（sh build/pack.sh 打出来）
bin/agent               给人用的入口（exec 回 seed.sh --agent）
bin/edit  bin/shell  bin/llm
tests/seed-package.sh   离线合同测试，不联网
docs/                   本文和规格
```

不进 git、也不属于种子的：

```text
.env                    本机钥匙
.agent-runs/            你用 agent 干活的证据
index.html 等           模型在这个工作区里造的东西
```

「只需要这颗种子」指的是：**换机器、换项目，带走 `seed.sh`（外加薄入口和测试）就够。** 不是说模型会把 `bin/agent` 从零写一遍。`bin/*` 是种子写的；模型写的是你项目里的代码。

## 9. 怎么用

依赖：`/bin/sh`、curl、jq。Linux、macOS、WSL、Git Bash 可以。

```sh
sh seed.sh deepseek sk-xxxx    # 装到当前目录
sh bin/agent                   # 交互
sh bin/agent "把 README 里的标题改短一点"   # 一次性
/bin/sh tests/seed-package.sh  # 离线验收
```

换到另一个项目：

```sh
cd ~/code/别的仓库
sh /path/to/slab/bin/agent
```

它改的是 `~/code/别的仓库`，不是 slab 自己。

在 Apple 的 `container` 里用 Debian 复现过：同一份种子，`/bin/sh` 是 dash，离线测试和真 DeepSeek 改文件都通过。容器里 DNS 有时要自己带 `--dns 8.8.8.8`。

---

## 10. 明确拒绝的路

- 用 Python / Perl / Ruby 实现 loop、edit、拼 SSE
- 为 Mac / Linux 维护两份种子
- 把工作区写死成本机路径
- 种子对人直播思考或模型正文
- 工具动物园
- 统一塞进 Bash 5 容器，假装宿主不存在
- 声称纯 shell 能对模型藏住 API Key（key 在用户自己的 `.env` 里）
- 原生 cmd.exe 版（那是另一种语言，不是这个实验）

---

## 11. 成功长什么样

人的感觉：装的时候终端几乎只有 token 在跳；用的时候像一个话少的同事，先看再改，改完自己检查，最后说一句人话。

机器的感觉：同一份 `seed.sh` 在 zsh 的 Mac 和 dash 的 Debian 上都能装、都能改文件；产物不携带旧电脑的住址；证据里能看到它真的调了 shell 和 edit，不是只会说话。

这就是 slab。一颗种子，一个循环，两个工具。其余的，让它在你的项目里长。
